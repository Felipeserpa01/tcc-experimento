🚀 ENDPOINTS DA API
═══════════════════════════════════════════════════════════════════════════════

AUTENTICAÇÃO
  POST   /api/auth/register          Registrar novo usuário
  POST   /api/auth/login             Login e obter token JWT

LIVROS
  POST   /api/books/                 Criar livro (bibliotecário)
  GET    /api/books/                 Listar todos os livros
  GET    /api/books/{id}             Obter detalhes de um livro
  PUT    /api/books/{id}             Atualizar livro (bibliotecário)
  DELETE /api/books/{id}             Deletar livro (bibliotecário)
  GET    /api/books/search/by-title  Buscar por título
  GET    /api/books/search/by-author Buscar por autor

EMPRÉSTIMOS
  POST   /api/loans/                    Emprestar um livro
  GET    /api/loans/                    Listar todos (bibliotecário)
  GET    /api/loans/my-loans            Meus empréstimos
  GET    /api/loans/active-loans/{id}   Empréstimos ativos de usuário
  GET    /api/loans/{id}                Detalhes do empréstimo
  POST   /api/loans/{id}/return         Devolver livro

UTILITÁRIOS
  GET    /                            Status da API
  GET    /health                      Health check
  GET    /docs                        Documentação Swagger (interativa)
  GET    /redoc                       Documentação ReDoc

📊 FLUXO DE DADOS
═══════════════════════════════════════════════════════════════════════════════

FLUXO DE AUTENTICAÇÃO:
  1. Cliente: POST /api/auth/login (username, password)
  2. Server: Valida credenciais no banco
  3. Server: Gera JWT com user_id no payload
  4. Cliente: Armazena token
  5. Cliente: Envia "Authorization: Bearer <token>" em requisições

FLUXO DE EMPRÉSTIMO:
  1. Cliente: POST /api/loans (book_id)
  2. Server: Valida token JWT → extrai user_id
  3. Server: Valida limite (max 3 ativos)
  4. Server: Valida livro existe
  5. Server: Valida exemplares disponíveis
  6. Server: Cria registro Loan
  7. Server: Decrementa available_quantity
  8. Server: Retorna dados do empréstimo

FLUXO DE DEVOLUÇÃO:
  1. Cliente: POST /api/loans/{id}/return (return_date)
  2. Server: Valida token e propriedade
  3. Server: Calcula multa se há atraso
  4. Server: Incrementa available_quantity
  5. Server: Atualiza return_date e fine
  6. Server: Retorna empréstimo finalizado
