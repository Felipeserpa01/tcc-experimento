🚀 COMO USAR
─────────────────────────────────────────────────────────────────────────────

1. INSTALAR DEPENDÊNCIAS
   $ pip install -r requirements.txt

2. RODAR A APLICAÇÃO
   $ uvicorn app.main:app --reload
   → Acesse: http://localhost:8000

3. ACESSAR DOCUMENTAÇÃO
   → Swagger: http://localhost:8000/docs
   → ReDoc: http://localhost:8000/redoc

4. EXECUTAR TESTES
   $ pytest tests/ -v

5. RODAR EXEMPLO
   $ python3 example_usage.py

🔗 ENDPOINTS PRINCIPAIS
─────────────────────────────────────────────────────────────────────────────

AUTENTICAÇÃO:
  POST   /auth/register          Registrar novo usuário
  POST   /auth/login             Fazer login

LIVROS:
  POST   /books/                 Criar livro (bibliotecário)
  GET    /books/                 Listar todos os livros
  GET    /books/{id}             Obter livro específico
  GET    /books/search           Buscar por título/autor
  PUT    /books/{id}             Atualizar livro (bibliotecário)
  DELETE /books/{id}             Deletar livro (bibliotecário)

EMPRÉSTIMOS:
  POST   /loans/                 Emprestar livro
  GET    /loans/user/active      Listar meus empréstimos ativos
  GET    /loans/{id}             Obter detalhes do empréstimo
  POST   /loans/return           Devolver livro

UTILITÁRIOS:
  GET    /                       Info da API
  GET    /health                 Health check
  GET    /docs                   Documentação Swagger
  GET    /redoc                  Documentação ReDoc

📋 MODELOS DE DADOS
─────────────────────────────────────────────────────────────────────────────

USER
  • id (PK)
  • username (UNIQUE, 3-50 chars)
  • email (UNIQUE, validado)
  • hashed_password (bcrypt)
  • user_type (ENUM: librarian, reader)
  • is_active (BOOL)

BOOK
  • id (PK)
  • title (INDEX)
  • author (INDEX)
  • isbn (UNIQUE, validado)
  • year (1000-2100)
  • total_quantity
  • available_quantity (auto-atualizado)
  • description (NULLABLE)

LOAN
  • id (PK)
  • user_id (FK → User)
  • book_id (FK → Book)
  • loan_date (DEFAULT: now)
  • due_date (loan_date + 14 dias)
  • return_date (NULLABLE)
  • status (ENUM: active, returned, overdue)
  • fine_amount (calculado: dias_atraso × 5.0)
